## CAN을 쓰는 이유
- 도구 여러 개가 같은 데이터를 동시에 소비할 수 있다는 뜻이다.
즉, 데이터 디버깅과, 로그 저장, 그래프와 등 동시에 작업이 가능하다.
- 원인 분리
position 문제인지, actuator 문제인지, comm 문제인지 빨리 분리 가능
- 관측/로그 때문에 1ms 루프가 흔들리는 걸 줄임
- ID 계약의 장점
문자열 로그 방식
'''[PosCtrl] EN:1 FLT:0 CMD:12/ACTIVE/NONE Target:3.00 Current:2.20 Error:0.80 Out:1500'''
장점 : 사람이 바로 읽기 좋음
단점 : 
-- PC가 다시 파싱해야 함
-- 문자열 길이가 가변
-- 항목 순서 바뀌면 툴이 깨짐
-- “encoder만 보고 싶다” 같은 선택 구독이 어려움
ID 계약 방식

예:

0x180 = POSITION_STATE
0x181 = ACTUATOR_STATE
0x182 = ENCODER_STATE

장점:

-- 무슨 데이터인지 ID만 보고 즉시 앎
-- payload 위치가 고정
-- 파서가 단순
-- 필요한 프레임만 선택 가능
-- 문자열 포맷 변경 리스크 없음
=> 사람이 눈으로 읽는 것보다, PC 툴/로거/스크립트가 안정적으로 처리하기 좋다
