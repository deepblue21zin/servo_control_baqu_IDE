- 무엇을 어떻게 바꿨는지:
  - `STEERING_GEAR_RATIO`를 `12.0f -> 12.5f`로 변경함
  - `ENCODER_QUADRATURE` 주석도 현재 프로젝트 기준에 맞게 `TIM2`에서 `TIM4` encoder mode 설명으로 정리함
  - steering portal의 정적 설명에서 기어비를 `12.5 : 1`로 바꾸고, `motor deg`, `encoder count`, `pulse` 파생 수치를 모두 새 기어비 기준으로 갱신함
  - `app.js` 시뮬레이션 계산식도 `12.5:1`, `1666.67 count / steering_deg`, `4166.67 pulse / steering_deg` 기준으로 바꾸고 lifecycle 예시의 `target_motor_deg`도 함께 수정함
- 수정 이유:
  - 실제 기구 기어비가 `12.5:1`인데 코드와 포털이 `12.0:1`을 기준으로 계산하고 있어 steering -> motor 변환, 예상 encoder count, 예상 pulse budget이 모두 실제와 어긋나고 있었음
  - bench 중 target / current / pulse budget을 해석할 때 문서와 코드 기준이 다르면 혼선이 커지므로 상수와 설명 자료를 같은 기준으로 맞출 필요가 있었음
- 영향 범위:
  - `SteeringDegToMotorDeg()`, `MotorDegToSteeringDeg()`를 사용하는 전체 제어 경로
  - portal 시뮬레이션의 모터각, 엔코더 카운트, 펄스 예산 표시
  - 이후 bench에서 1 steering degree당 기대되는 motor/pulse/count 해석 기준

## 03-25-02 01:09:14

- 수정 파일:
  - `Core/Inc/position_control.h`
  - `Core/Inc/position_control_diag.h`
  - `Core/Src/position_control.c`
  - `Core/Src/position_control_diag.c`
  - `Doc/change_code/2026-03-25.md`
- 무엇을 어떻게 바꿨는지:
  - `position_control.c`에서 command/source/result 문자열 변환, debug var 동기화, 상태 출력 같은 진단 책임을 제거하고 제어 루프, lifecycle, safety, enable/disable 중심으로 정리함
  - 새 파일 `position_control_diag.c/.h`를 추가해 debug var 갱신, 상태 출력, 에러 문자열 변환, diagnostic API stub을 한곳에서 관리하도록 분리함
  - `position_control.c`에는 진단 동기화를 위한 얇은 helper와 `PrintStatus()` wrapper만 남겨서 핫패스가 직접 debug 전역을 다루지 않도록 정리함
  - 핵심 static helper와 public 함수 위주로 짧은 설명 주석을 추가해 함수 역할이 바로 보이도록 정리함
  - `position_control.h`의 오래된 `12:1` 주석은 현재 기어비 상수와 충돌하지 않도록 일반화함
- 수정 이유:
  - 제어 루프와 진단/출력 책임이 한 파일에 섞여 있어 유지보수와 리뷰 시 핵심 로직을 따라가기 어려웠음
  - 이후 `fault latch`, startup contract, timing base 개선을 진행할 때도 제어 코어와 진단 계층이 나뉘어 있어야 변경 영향 범위를 줄일 수 있음
  - 파일을 분리하면서 함수 설명을 함께 보강하면 bench 중 빠르게 함수 역할을 파악하기 쉬워짐
- 영향 범위:
  - `PositionControl_Update()`와 관련 lifecycle/safety 경로의 코드 가독성 및 유지보수 방식
  - `PrintStatus()`, `GetErrorString()`, debug var 미러링, 향후 diagnostic 확장 포인트
  - `position_control` 관련 파일을 읽는 개발자의 진입 난이도
