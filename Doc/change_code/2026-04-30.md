- 수정 이유:
  - UART 로그에서 `adc_valid=0x00`인 정상 샘플에도 `adc_age=30~40ms`가 찍히며 `adc_stale_warn`이 반복됐다.
  - 기존 `age_ms`는 "현재 샘플의 나이"가 아니라 "이전 샘플과 이번 샘플 사이의 간격"으로 계산되어 app runtime sensor supervisor가 정상 ADC 샘플을 stale로 오판했다.
  - Windows가 `61231~61330` TCP 포트 범위를 예약해 CubeIDE 기본 GDB/SWV 포트 `61234/61235`를 사용할 수 없었다.
- 영향 범위:
  - 정상 ADC 변환 샘플은 `adc_age_ms=0`으로 보고되어 `adc_stale_warn` 오탐이 줄어든다.
  - 실제 ADC 변환 timeout은 `ADC_POT_INVALID_TIMEOUT`으로 명확히 구분되어 기존 fault 판단 경로가 계속 동작한다.
  - `sensor_crosscheck_warn`은 더 이상 ADC stale 오탐과 섞이지 않고, encoder-vs-ADC 각도 차이 자체를 나타내는 경고로 해석할 수 있다.
