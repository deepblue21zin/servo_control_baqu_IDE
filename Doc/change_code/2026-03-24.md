## 03-24-01 18:31

- 파일:
  - `Core/Src/main.c`
  - `Doc/change_code/2026-03-24.md`
- 이유:
  - `TIM4->CNT` raw 값이 고정될 때 원인이 입력 파형 부족인지, encoder mode 레지스터 설정 불일치인지, 채널 enable 문제인지 런타임에서 바로 분리할 수 있는 진단 로그가 필요했음
- 수정 내용:
  - `ENCODER_RUNTIME_DIAG_ENABLE`, `ENCODER_RUNTIME_DIAG_PERIOD_MS` 매크로를 추가해 엔코더 런타임 진단 로그를 독립적으로 켜고 끌 수 있게 함
  - 1ms 루프에서 100ms마다 `cnt`, `prev`, `delta`, `PD12/PD13` 입력 상태와 `TIM4`의 `CR1`, `SMCR`, `CCMR1`, `CCER` 핵심 비트를 함께 출력하는 `[ENCDBG]` 로그를 추가함
  - 로그에 `CEN`, `SMS`, `CC1S`, `CC2S`, `CC1E`, `CC2E`를 분리 표기해 타이머 기동 여부, encoder mode 유지 여부, 채널 선택/enable 상태를 한 줄에서 확인할 수 있게 함
- 영향:
  - `PD12/PD13`에 파형이 보이는데도 `ENC`가 고정되는 상황에서, 실제로 `CNT` 변화가 없는지와 `TIM4`가 encoder 인터페이스 상태를 유지하는지를 UART 로그만으로 더 빠르게 판별할 수 있게 됨
  - 이후 bench 진단에서 하드웨어 입력 체인 문제와 타이머 설정 문제를 분리하는 시간이 줄어듦

## 03-24-02 20:26

- 파일:
  - `Core/Src/main.c`
  - `Doc/change_code/2026-03-24.md`
- 이유:
  - 엔코더 경로 확인 후 구동 출력 체인을 다시 테스트하기 위해, 오늘 추가한 `[ENCDBG]` UART 진단이 제어 주기에 주는 영향을 우선 배제할 필요가 있었음
- 수정 내용:
  - `ENCODER_RUNTIME_DIAG_ENABLE` 값을 `1 -> 0`으로 변경해 오늘 추가한 엔코더 런타임 진단 로그만 비활성화함
  - 진단 함수 본문은 유지해 필요 시 매크로만 다시 `1`로 바꿔 재사용할 수 있게 둠
- 영향:
  - `[ENCDBG]` 출력이 멈춰 UART 블로킹 부하를 줄인 상태에서 모터 구동 여부를 다시 확인할 수 있게 됨
  - 기존 CSV/키보드/상태 로그는 그대로 유지되므로, 엔코더 디버그를 제외한 원래 런타임 관찰 흐름은 계속 사용할 수 있음
