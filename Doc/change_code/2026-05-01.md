- 수정 이유

  - 현재 테스트 방향에 맞춰 `CAN_ENCODER_BRIDGE_ENABLE`을 `0`으로 바꿔 USART1-to-CAN encoder bridge를 비활성화했다.
  - USART2를 RS422 엔코더 수신용으로 사용하도록 baudrate를 `RS422_ENCODER_UART_BAUDRATE`로 연결하고 `UART_MODE_RX`로 변경했다.
  - USART2 MSP GPIO 설정에서 PA3 RX만 초기화하도록 정리했다.
  - AppRuntime 초기화/루프에 `Rs422Encoder_Init()`과 `Rs422Encoder_Service()`를 연결했다.

- 수정 이유
  - `rs422_encoder_uart.c`는 정확히 4바이트 little-endian signed count 프레임만 디코딩하도록 만들어져 있는데, 필수 설정 매크로가 정의되지 않아 `#error`와 `RS422_ENCODER_FRAME_SIZE undeclared` 빌드 오류가 발생했다.
  - CAN을 사용하지 않고 RS422로 직접 엔코더 값을 확인하기로 했으므로 USART2 PA3 RX 경로를 실제 런타임에 연결해야 했다.

- 영향 범위
  - 부팅 후 Putty 로그에 `[RS422] ready uart=USART2_RX pin=PA3 baud=38400 frame=4 bytes` 형태의 준비 로그가 출력된다.
  - RS422 수신선은 USART2 RX인 PA3로 들어와야 하며, 수신 데이터는 4바이트 little-endian signed count여야 한다.
  - 기존 CAN encoder bridge는 현재 빌드에서 동작하지 않는다.

- 영향 범위

  - `S`는 기존처럼 목표값을 0도로 보내는 명령이고, `Z`는 현재 위치 자체를 0도로 재정의하는 명령이다.
  - RS422 로그의 `Current Deg`는 zero 설정 전에는 raw count 기준, zero 설정 후에는 `raw_count - zero_count` 기준으로 출력된다.
