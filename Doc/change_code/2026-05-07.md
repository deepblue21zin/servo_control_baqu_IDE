- 수정 이유
  - 현재 시스템은 CAN을 쓰지 않고 RS422 encoder 경로만 사용하기로 했으므로 CAN peripheral, runtime, bridge 코드가 남아 있으면 CubeMX 재생성/빌드/디버깅 기준이 섞인다.
  - `project_params.h`에 중복 define과 이전 감속기 기준 값이 섞여 있어 실제 적용값을 한눈에 판단하기 어려웠다.
  - RS422/TIM2 sensor-supervisor가 `PositionControl_UpdateWithCurrentAngle()`를 호출하지만 header 선언이 없어 빌드 경고 또는 오류가 날 수 있었다.
  - ADC polarity 설정은 선언되어 있었지만 변환 결과에 반영되지 않아 실제 polarity flip 시 각도 계산이 틀릴 수 있었다.

- 영향 범위
  - 활성 펌웨어 초기화 경로는 `GPIO`, `USART3`, `ADC1`, `TIM1`, `IWDG`, `LWIP`, `TIM2`, `USART2` 중심으로 정리된다.
  - RS422 encoder 수신은 `USART2_RX=PA3`, 38400 baud, RX-only 기준으로 유지된다.
  - CAN1 PD0/PD1과 USART1 PA9/PA10은 CubeMX 설정과 앱 코드에서 더 이상 활성 주변장치로 초기화되지 않는다.
  - STM32 startup vector의 CAN/USART1 IRQ 이름은 MCU 공용 vector table 항목이므로 기능 활성화와 무관하게 남는다.
  - 과거 change log와 일부 장기 문서에는 히스토리 목적의 CAN 언급이 남아 있을 수 있으나, 현재 활성 코드/IOC 경로에서는 CAN을 제거했다.
