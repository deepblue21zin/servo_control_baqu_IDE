- 이유:
  - homing 없이도 조향 명령 하나의 시작, 완료, 중단, timeout을 로그와 상태로 추적할 수 있게 실제 코드 경로에 command lifecycle을 반영할 필요가 있었음
- 수정 내용:
  - `CommandLifecycle_t`, `CommandState_t`, `CommandSource_t`, `CommandResult_t`를 추가하고 `command_id` 기반 명령 상태를 추적하도록 확장함
  - `PositionControl_SetTargetWithSource()`를 추가해 키보드, UDP, service 등 명령 출처를 함께 기록하고, 새 명령 수락 시 기존 active 명령을 `REPLACED`로 종료하도록 반영함
  - `CMD_START`, `CMD_REACHED`, `CMD_TIMEOUT`, `CMD_ABORT`, `CMD_FAULT` 이벤트 로그를 UART에 남기도록 추가함
  - timeout fault를 디버그 비트플래그로 분리하고, CSV / snapshot / DIAG 출력에 `cmd_id`, `cmd_state`, `cmd_result`를 포함하도록 확장함
  - `CMD_REACHED` 이후에는 펄스를 즉시 정지하고 새 명령 전까지 완료 상태를 유지하도록 보강해 "명령 완료" 의미를 runtime 동작과 맞춤
  - spec 문서에도 `CMD_REACHED` 직후 pulse stop과 완료 상태 유지 정책을 반영해 코드와 명세를 일치시킴
- 영향:
  - bench 환경에서도 "몇 번째 명령이 언제 시작되어 어떤 결과로 끝났는지"를 로그만으로 추적할 수 있게 됨
  - homing 미완성 상태에서도 command lifecycle 검증과 timeout/abort/fault 시나리오 테스트가 가능해짐
  - CSV, snapshot, DIAG, debug var를 함께 보면 조향 명령 단위의 수행 결과를 더 명확히 분석할 수 있게 됨
